# Feature-ML: каналы и признаки

Актуально на 16.10.2026. Этот файл — компактная сводка фактической реализации.
Подробное описание всего алгоритма находится в
[`feature-ml-complete-guide.md`](feature-ml-complete-guide.md).

## Профили и размерность вектора

Доступны три воспроизводимые карты признаков:

| Профиль | Состав | Число |
|---|---|---:|
| `reference_sxr` | локальная форма опорного SXR и пять D-alpha | 50 |
| `core_diagnostics` | опорный и все SXR, proposals, D-alpha, МГД и ФДУК | 160 |
| `full` | core и остальные диагностические группы | 224 |

Профиль по умолчанию — `core_diagnostics`. `full` выбирается явно для
сравнительного эксперимента с менее приоритетными диагностическими группами.

Для профиля `full` вектор раскладывается так:

| Блок | Расчёт | Число |
|---|---:|---:|
| Локальная форма опорного SXR | 16 | 16 |
| Пять SXR-каналов | 5 × 11 | 55 |
| Двадцать диагностических каналов | 20 × 6 | 120 |
| Семь агрегированных групп диагностик | 7 × 4 | 28 |
| Свойства совокупности proposals | 5 | 5 |
| **Итого** |  | **224** |

Порядок столбцов формирует `MultichannelFeatureBuilder`. Он сохраняется вместе
с моделью и проверяется при загрузке. Любое изменение состава или формулы
признаков требует переобучения.

Текущая схема признаков имеет версию 2. Версия 2 удаляет токи плазмы из
классификатора, добавляет ФДУК и вводит экстремум-признаки MHD/ФДУК.

## Временное окно и нормализация

Для многоканальных признаков используется симметричное окно вокруг кандидата:

```text
window = clip(0.25 × period, 0.2 ms, 1.0 ms)
```

Каждый сигнал независимо robust-нормируется по всему плазменному интервалу:
из него вычитается медиана, масштаб равен `1.4826 × MAD`; при вырожденном MAD
используется стандартное отклонение, затем единица. Диагностические каналы с
другой временной сеткой линейно интерполируются на сетку опорного SXR. Разрывы,
края и отсутствующие отсчёты сохраняются через `valid_mask`, а не заполняются
произвольными значениями.

Опорный SXR для каждого разряда выбирается автоматически среди доступных SXR
по максимальному отношению стандартного отклонения в плазме к шуму до плазмы.
Минимально допустимый SNR для ML равен 2.

Канал, запрошенный пользователем для итогового графика, проверяется отдельно.
Если он существует и имеет `SNR >= 2`, найденные события показываются именно на
нём, даже когда модель использовала другой опорный SXR. Если канал отсутствует,
его SNR нельзя вычислить или `SNR < 2`, график переключается на автоматически
выбранный самый надёжный SXR. В лог записываются причина переключения, имя и SNR
запрошенного канала, порог и имя/SNR выбранного канала. Это правило влияет
только на визуализацию, а не на признаки или ответы модели.

## Опорный SXR: 16 признаков локальной формы

Это исторический блок `sxr__*`, вычисляемый на автоматически выбранном опорном
SXR функцией `extract_candidate_features()`.

| Признак | Смысл |
|---|---|
| `physics_score` | `max(0, amp_score) + 0.15 × slope_score` |
| `amp_score` | величина скачка относительно robust-разброса амплитуды |
| `slope_score` | экстремальная производная относительно robust-разброса производной |
| `normal_drop` | `p90(pre) − p10(post)`, обычное падение |
| `inverted_rise` | `p90(post) − p10(pre)`, инвертированный рост |
| `seg_mean` | среднее локального сегмента |
| `seg_std` | стандартное отклонение сегмента |
| `seg_mad` | robust-разброс сегмента |
| `seg_peak_to_peak` | полный размах `max − min` |
| `min_derivative` | минимальная производная |
| `max_derivative` | максимальная производная |
| `std_derivative` | стандартное отклонение производной |
| `kurtosis` | эксцесс/импульсность локальной формы, Pearson kurtosis |
| `skew` | асимметрия распределения значений |
| `post_minus_pre_mean` | изменение среднего после кандидата |
| `post_std_over_pre_std` | отношение разброса после и до кандидата |

Для этого блока окно немного шире: радиус равен
`clip(0.25 × period, 0.2 ms, 2 ms)`, минимум 10 отсчётов.

## SXR-каналы: 55 признаков

| Имя канала в SHT | Роль |
|---|---|
| `SXR 15 мкм` | многоканальный teacher, proposals и 11 признаков формы/качества |
| `SXR 27 мкм` | многоканальный teacher, proposals и 11 признаков формы/качества |
| `SXR 50 mkm` | многоканальный teacher, proposals и 11 признаков формы/качества |
| `SXR 80 mkm` | многоканальный teacher, proposals и 11 признаков формы/качества |
| `SXR 127 мкм` | многоканальный teacher, proposals и 11 признаков формы/качества |

Для каждого SXR создаётся одинаковый набор:

| Суффикс | Смысл |
|---|---|
| `present` | канал существует в этом разряде |
| `proposed` | этот SXR поддержал объединённый кандидат |
| `proposed_posr` | на канале был POSR-кандидат |
| `proposed_cpd` | на канале был raw CPD-кандидат |
| `median_delta_z` | разность медиан после и до события в robust-z единицах |
| `signed_jump_z` | доминирующий скачок: падение со знаком минус, рост со знаком плюс |
| `log_energy_ratio` | логарифм отношения RMS после и до события |
| `max_abs_period_slope` | максимальный модуль соседнего перепада, нормированный на период |
| `change_offset_period` | смещение сильнейшего перепада от кандидата в долях периода |
| `local_noise_z` | robust-разброс соседних разностей до и после события |
| `log_jump_to_noise` | `log1p(abs(median_delta_z) / local_noise_z)` |

Если SXR отсутствует, первые четыре индикатора равны нулю, остальные значения
помечаются как `NaN`. Используемые древовидные модели умеют обрабатывать такие
пропуски.

## Дополнительные диагностические каналы: 120 признаков

Профиль определён в `config/channels.py`. Все диагностические каналы дают по
шесть признаков, но их физический смысл зависит от группы.

`coverage` — доля валидных отсчётов в локальном окне. Остальные пять величин
имеют тот же смысл, что и одноимённые SXR-признаки выше.

Для D-alpha используются шесть специализированных признаков положительного
всплеска, ожидаемого около SXR-срыва:

| Суффикс | Смысл |
|---|---|
| `coverage` | доля валидных отсчётов в окне |
| `positive_peak_z` | превышение положительного максимума над медианой до события в robust-z единицах |
| `peak_prominence_z` | превышение максимума над большим из уровней до события и после пика |
| `positive_area_z` | средняя положительная площадь над предсобытийным уровнем |
| `rise_slope_period` | максимальный положительный соседний перепад до вершины, нормированный на период |
| `peak_offset_period` | смещение вершины D-alpha от SXR-кандидата в долях периода |

Для МГД и ФДУК используются признаки локального экстремума обоих знаков:

| Суффикс | Смысл |
|---|---|
| `coverage` | доля валидных отсчётов в окне |
| `signed_extremum_z` | наиболее сильное отклонение от предсобытийной медианы; знак различает максимум и минимум |
| `extremum_prominence_z` | выраженность экстремума относительно уровней слева и справа |
| `max_abs_period_slope` | максимальный модуль соседнего перепада, нормированный на период |
| `derivative_reversal_period` | меньшая из крутизны подхода к экстремуму и обратной крутизны ухода от него |
| `extremum_offset_period` | смещение экстремума от SXR-кандидата в долях периода |

Для остальных каналов полного профиля остаются универсальные `coverage`,

## Групповые агрегаты: 28 признаков

Для групп `plasma_position`, `voltage`, `radiometer` и `diamagnetic`
вычисляются:

| Суффикс | Агрегация внутри группы |
|---|---|
| `coverage` | среднее покрытие каналов |
| `median_delta_z` | медиана доступных `median_delta_z` |
| `max_abs_jump_z` | максимальный модуль `signed_jump_z` |
| `max_abs_period_slope` | максимальный модуль нормированной крутизны |

Эти признаки дают модели устойчивое групповое описание, если отдельный канал
отсутствует или зашумлён.

Для групп `mhd` и `fduk` используются `coverage`,
`median_abs_extremum_z`, `max_extremum_prominence_z` и
`extremum_support_fraction`. Последний признак равен доле доступных каналов с
prominence не меньше одной robust-z единицы.

Для группы `d_alpha` вместо универсальных агрегатов используются `coverage`,
`median_positive_peak_z`, `max_peak_prominence_z` и `peak_support_fraction`.
Последний признак равен доле доступных D-alpha каналов с prominence не меньше
одной robust-z единицы. Это информация для модели, а не жёсткий фильтр.

Ток плазмы не является ML-признаком. Он загружается отдельно и используется
для определения плазменного интервала и стартового gate: proposals до
установления тока на плато отбрасываются до классификации.

## Свойства proposals: 5 признаков

При обучении источник выбирается через `--ml_proposal_source`: `posr` (по
умолчанию), `cpd` или `hybrid`. При детектировании он читается из модели и не
передаётся отдельно.
Имя сохранённой модели содержит и источник proposals, и фактически выбранный
ML-backend и профиль, например `feature_ml_posr_sklearn_hgb_reference_sxr.joblib`
или `feature_ml_hybrid_catboost_full.joblib`.
В POSR-режиме feature-ML получает raw POSR peaks без physics/jump-фильтров,
sawtooth mask и period-NMS. В CPD-режиме используются raw breakpoints без
физической постфильтрации. `hybrid` объединяет оба списка. Каждый выбранный
источник запускается независимо на каждом доступном SXR. Близкие заявки
объединяются в один кандидат в окне 0.15 ms. Голосование для создания кандидата
не требуется; число поддержавших каналов передаётся модели как информация.
Режимы с CPD требуют установленного `ruptures` и не откатываются молча на POSR.
После классификатора глобальный period-NMS не используется. Штатная стратегия
`adaptive_period` рассматривает точки от большей `ml_probability` к меньшей и
подавляет соседей в радиусе
`clip(0.50 × local_period, 0.12 ms, 0.80 ms)`. Локальный период применяется при
confidence не меньше `0.20`; иначе используется fallback `0.50 ms`. При
сравнении двух точек берётся меньший радиус, поэтому одна завышенная оценка не
должна удалить короткопериодный срыв. Для ML карта ищется начиная с `0.5 ms`,
но алгоритмические детекторы сохраняют прежнюю нижнюю границу `1.0 ms`.

Доля `0.50` выбрана для случая, когда шумный или зашкаленный фронт одного срыва
даёт два положительных кандидата по разные стороны настоящего события. На
текущей экспертной выборке увеличение доли с `0.40` до `0.50` уменьшило число
таких дублей с 7 до 2 без потери найденных экспертных событий. Значение `0.60`
убирало оставшиеся дубли, но уже потеряло одно событие, поэтому оно не стало
штатным.

Строгая `period_map` остаётся входом генераторов proposals. Для финального
объединения отдельно подготовлены более полная `merge_period_map` и
`period_confidence_map`. Параметры NMS можно менять в `detect` без обучения;
режимы `fixed` и `statistical` оставлены для сравнительных экспериментов.

| Признак | Смысл |
|---|---|
| `source_channel_count` | число разных SXR, поддержавших кандидат |
| `method_count` | число разных методов среди источников |
| `proposal_count` | полное число объединённых заявок |
| `median_log_source_score` | медиана `log1p(score)` источников |
| `time_spread_period` | временной разброс заявок в долях периода |

Подробная последовательность построения raw POSR, raw CPD и межканального
объединения описана в разделе 7 полного руководства.

## Токовый gate перед proposals

Все профили получают один и тот же физически допустимый набор proposals. Ток
сглаживается окном 0.25 ms; плато оценивается 95-м процентилем. Кандидаты до
момента, когда ток остаётся выше 80% плато не менее 0.5 ms, удаляются до ML.
После открытия gate не закрывается на позднем спаде тока.

## Каналы teacher и смысл меток

Wavelet teacher запускается по всем доступным SXR с `SNR >= 2`. Пользователь не
задаёт опорный канал. Срабатывания объединяются по времени, и положительной
teacher-меткой становится только событие, подтверждённое минимум двумя разными
SXR. В `notSaw` положительные teacher-события намеренно отсутствуют.

Одиночные wavelet-срабатывания полностью отбрасываются и не отображаются.
Автоматических неопределённых teacher-меток больше нет. Все raw POSR/CPD
proposals, которые не попали в допуск подтверждённой wavelet- или ручной метки,
становятся отрицательными. Отдельно сохраняется только ручной экспертный статус
`uncertain`: он исключает сомнительную окрестность из обучения.

## Экспертные метки и каналы наблюдения

Ручная разметка из `../data/annotations/expert_events.json` имеет приоритет над
wavelet только внутри явно заданных `reviewed_intervals_s`. У события хранятся
только физическое время на полной шкале SHT и решение эксперта. Каналы для
признаков определяются программой; эксперт не выбирает опорный или видимые SXR.
Толщины фольги не создают отдельные копии одной метки.

События `sawtooth` становятся положительными, `uncertain` создают исключаемую
зону, а `false_positive` явно документируют неверные подсказки wavelet/POSR/CPD
или feature-ML. Остальные proposals в просмотренном интервале становятся
отрицательными. Вне
таких интервалов остаётся wavelet-разметка. Если raw-генератор не предложил
ручной срыв, на обучении добавляется кандидат в экспертном времени; отдельный
`expert_proposal_recall` всё равно считается до добавления и показывает
реальную полноту генератора.

На уровне разряда хранится решение `sawtooth`, `no_sawtooth` или `uncertain`.
`no_sawtooth` разрешён только для полностью просмотренного диапазона без
положительных меток. Заполнять схему можно через Streamlit-интерфейс
`src/detection/ml/annotation/app.py`; он показывает выбранные диагностические
каналы на их временных сетках и позволяет ставить метки независимо от
автоматических proposals.
